# v1.9.6 — ChatGPT's Chat/Work layout and signed-out Grok

## Provider-compatibility patch / Provider 相容性補丁

Multi-AI Chat Desktop `v1.9.6` covers two provider reports from one reporter on a zh-TW UI, both with debug bundles. [#118](https://github.com/teddashh/multi-ai-chat-desktop/pull/118), merged 2026-09-30, is for [#115](https://github.com/teddashh/multi-ai-chat-desktop/issues/115) (ChatGPT) and [#116](https://github.com/teddashh/multi-ai-chat-desktop/issues/116) (Grok). The release also bundles ChatGPT adapter v8 from [#114](https://github.com/teddashh/multi-ai-chat-desktop/pull/114), merged 2026-09-27, for [#113](https://github.com/teddashh/multi-ai-chat-desktop/issues/113). Adapter v8 recognizes ChatGPT's ProseMirror contenteditable composer (`.ProseMirror[contenteditable="true"]`) for prompt input and for Ready detection. It reached installed apps through the adapter update on 2026-09-27. No live desktop check has shown v8 working.

Multi-AI Chat Desktop `v1.9.6` 涵蓋同一位 zh-TW 介面回報者的兩則 provider 回報，兩則都附了 debug bundle。[#118](https://github.com/teddashh/multi-ai-chat-desktop/pull/118) 於 2026-09-30 合併，對應 [#115](https://github.com/teddashh/multi-ai-chat-desktop/issues/115)（ChatGPT）與 [#116](https://github.com/teddashh/multi-ai-chat-desktop/issues/116)（Grok）。這次發行也一併包含 ChatGPT adapter v8，來自 [#114](https://github.com/teddashh/multi-ai-chat-desktop/pull/114)（2026-09-27 合併），對應 [#113](https://github.com/teddashh/multi-ai-chat-desktop/issues/113)。Adapter v8 認得 ChatGPT 的 ProseMirror contenteditable 輸入框（`.ProseMirror[contenteditable="true"]`），用在提示輸入，也用來判斷 Ready。已安裝的 app 在 2026-09-27 經由 adapter 更新收到 v8。還沒有實機桌面檢查顯示 v8 能運作。

[#116](https://github.com/teddashh/multi-ai-chat-desktop/issues/116): the reporter was not signed in to Grok. On anonymous grok.com the Sign in / Sign up controls are links (`<a data-slot="button">`), not buttons, and the submit button (`chat-submit`) stays visible. Grok adapter v7's `loggedOutDetectors` only matched button text, and `chat-submit` matched `loginDetectors`, so the pane said Ready. After the send, Grok showed its anonymous sign-up paywall. Grok adapter v7 → v8 keeps every existing detector and appends three signed-out detectors: `[data-testid="anon-paywall-sign-up-card"]`, `a[href^="/sign-in"]`, and `a[href^="/sign-up"]`. The `^=` prefix match means a reply that links to `https://example.com/sign-in` keeps the pane Ready; a test covers that. The change is adapter-only. Installed `v1.9.5` apps pick it up through the adapter update, at startup and every six hours, since #118 merged on 2026-09-30. `v1.9.6` bundles it. A logged-out Chromium probe of `https://grok.com/` on 2026-09-30, in en-US and zh-TW, with no sign-in and no send, showed `a[href="/sign-in?return_to=%2F"]` and `a[href="/sign-up?return_to=%2F"]`. Grok's production JavaScript, fetched the same day, renders those two links only in its anonymous header, when there is no session user. The paywall card is its anonymous sign-up card. No signed-in page was captured live.

[#116](https://github.com/teddashh/multi-ai-chat-desktop/issues/116)：回報者當時沒有登入 Grok。在匿名的 grok.com 上，Sign in／Sign up 是連結（`<a data-slot="button">`），不是按鈕，送出按鈕（`chat-submit`）一直留在畫面上。Grok adapter v7 的 `loggedOutDetectors` 只比對按鈕文字，而 `chat-submit` 又符合 `loginDetectors`，窗格因此顯示 Ready。送出之後，Grok 顯示匿名註冊付費牆。Grok adapter 從 v7 到 v8 保留每一個既有偵測器，並附上三個未登入偵測器：`[data-testid="anon-paywall-sign-up-card"]`、`a[href^="/sign-in"]`、`a[href^="/sign-up"]`。`^=` 是前綴比對，所以回覆若連到 `https://example.com/sign-in`，窗格仍維持 Ready；有一項測試覆蓋這件事。這項變更只有 adapter。#118 於 2026-09-30 合併後，已安裝的 `v1.9.5` 會經由 adapter 更新（啟動時與每六小時一次）取得它。`v1.9.6` 把它收進發行內容。2026-09-30 以未登入的 Chromium 探查 `https://grok.com/`，語系為 en-US 與 zh-TW，沒有登入、也沒有送出，畫面上是 `a[href="/sign-in?return_to=%2F"]` 與 `a[href="/sign-up?return_to=%2F"]`。同一天抓下的 grok.com 正式版 JavaScript，只在沒有登入使用者時，才在匿名頁首畫出這兩條連結。付費牆卡片是它的匿名註冊卡。沒有實機擷取過已登入的頁面。

[#115](https://github.com/teddashh/multi-ai-chat-desktop/issues/115): the reporter's signed-in account has ChatGPT's newer Chat/Work layout, which OpenAI rolled out per account around 2026-09-25 to 2026-09-28. It dropped `data-message-author-role`, `article`, and the `conversation-turn` test ids. `v1.9.5` could not confirm the send, find the reply, or see completion. The debug digest showed `responseSelectors` 0/2 on a `/c/<id>` page. In `injected/engine.ts`, the user's `[data-user-message-bubble]` anchors send confirmation, so one automatic click is enough. A `[data-turn-key]` exchange counts as the completion turn even though it also holds the prompt. A `.turn-action-controls` button that follows the answer counts as completion. Controls inside the user's own message (Copy message / Share prompt / Edit message) never count as completion or as history. Text inside the user's own message is never read as an activity label, so a prompt that is literally `Pro thinking` still finishes, while a real `Pro thinking` status keeps the exchange active and blocks a new send.

[#115](https://github.com/teddashh/multi-ai-chat-desktop/issues/115)：回報者已登入的帳號是 ChatGPT 較新的 Chat/Work 版面。OpenAI 大約在 2026-09-25 到 2026-09-28 之間，按帳號推出這個版面。它拿掉了 `data-message-author-role`、`article`，以及 `conversation-turn` 的 test id。`v1.9.5` 無法確認送出、找不到回覆，也看不到完成。debug digest 在 `/c/<id>` 頁面顯示 `responseSelectors` 0/2。在 `injected/engine.ts` 裡，使用者的 `[data-user-message-bubble]` 用來錨定送出確認，所以自動點擊一次就夠。一個 `[data-turn-key]` 交換即使同時包著提示，也算完成回合。跟在答案後面的 `.turn-action-controls` 按鈕算完成。使用者自己那則訊息裡的控制項（Copy message／Share prompt／Edit message）不算完成，也不算歷史。使用者自己那則訊息裡的文字不會被讀成活動標籤，所以提示字面就是 `Pro thinking` 時，回合仍會結束；真正的 `Pro thinking` 狀態會讓這次交換維持進行中，並擋住新的送出。

ChatGPT adapter v8 → v9 appends `[data-markdown-text-style="assistant-message"]:not([data-markdown-text-tone="tertiary"])` for the answer. The tertiary tone is a status line, not the answer. The screen-reader-only "ChatGPT said:" heading is deliberately not a response selector. The older selectors are unchanged and still used on the legacy layout. Installed `v1.9.5` apps pick up adapter v9 the same way, but `v1.9.5` plus adapter v9 still cannot confirm send or completion on the Chat/Work layout. The engine half ships only in `v1.9.6`. Evidence is the #115 debug digest, plus public reports and real captures of the Chat/Work DOM: [steipete/oracle#517](https://github.com/steipete/oracle/issues/517) and commit [9851cb3](https://github.com/steipete/oracle/commit/9851cb34d5549b4bcda5a0e2e27e69d709a9e85a), [avivsinai/yoetz](https://github.com/avivsinai/yoetz), and the 2026-09-29 captures in [syamnadhg/dg-research-backend `tests/fixtures/chatgpt_0928`](https://github.com/syamnadhg/dg-research-backend/tree/master/tests/fixtures/chatgpt_0928). No Chat/Work account was available for a live check. The owner-approved `docs/SPEC.md` §5.1 amendment records ChatGPT adapter v9 and Grok adapter v8.

ChatGPT adapter 從 v8 到 v9，為答案多加 `[data-markdown-text-style="assistant-message"]:not([data-markdown-text-tone="tertiary"])`。`tertiary` 色調是狀態列，不是答案。僅供螢幕閱讀器的標題「ChatGPT said:」刻意不當成 response selector。較舊的 selector 沒有改，舊版面仍用它們。已安裝的 `v1.9.5` 也用同樣方式取得 adapter v9，但 `v1.9.5` 加上 adapter v9 仍然無法在 Chat/Work 版面上確認送出或完成。engine 那一半只隨 `v1.9.6` 出貨。依據是 #115 的 debug digest，以及 Chat/Work DOM 的公開報告與實際擷取：[steipete/oracle#517](https://github.com/steipete/oracle/issues/517)、commit [9851cb3](https://github.com/steipete/oracle/commit/9851cb34d5549b4bcda5a0e2e27e69d709a9e85a)、[avivsinai/yoetz](https://github.com/avivsinai/yoetz)，以及 2026-09-29 收在 [syamnadhg/dg-research-backend `tests/fixtures/chatgpt_0928`](https://github.com/syamnadhg/dg-research-backend/tree/master/tests/fixtures/chatgpt_0928) 的擷取。沒有 Chat/Work 帳號可以做實機檢查。擁有者已核准的 `docs/SPEC.md` §5.1 修訂記下 ChatGPT adapter v9 與 Grok adapter v8。

## Verification / 驗證

- `pnpm verify` passed locally on the #118 tree: injected build, TypeScript, ESLint, 770 frontend tests in 63 files (755 before #118), 22 Agent contract tests, and adapter schema and selector checks. `cargo test` was not run. There is no Rust change, and this Linux host lacks `libdbus-1-dev`.
- 在 #118 這棵樹上，本機的 `pnpm verify` 通過：injected 建置、TypeScript、ESLint、63 個檔案共 770 項前端測試（#118 之前是 755）、22 項 Agent contract 測試，以及 adapter 的 schema 與 selector 檢查。沒有跑 `cargo test`。沒有 Rust 變更，而且這台 Linux 主機沒有 `libdbus-1-dev`。
- CI on the final #118 head `0a3b06b` passed: `frontend`, `adapters`, `cargo-clippy` on ubuntu, macOS, and Windows, and CodeQL (actions, javascript-typescript, rust). The first run, on `1cf2f0e`, failed `frontend`: three Chat/Work tests hit vitest's 5 s per-test timeout. They keep a wait open through a 13.4 s fake-time window, and every 10 ms poll re-parsed every selector for every element in the test fake DOM. `1a8d256` caches parsed selectors there. The test file drops from 8.0 s to 0.8 s locally and the slowest Chat/Work test from 1.8 s to 90 ms. No assertion changed.
- #118 最後的 head `0a3b06b` 的 CI 通過：`frontend`、`adapters`、ubuntu、macOS 與 Windows 上的 `cargo-clippy`，以及 CodeQL（actions、javascript-typescript、rust）。第一次在 `1cf2f0e` 上跑的 `frontend` 失敗：三項 Chat/Work 測試碰到 vitest 每項測試 5 秒的逾時。這些測試讓一次等待跨過 13.4 秒的模擬時間，而測試用假 DOM 在每 10 毫秒的輪詢裡，都對每個元素重新解析每一個 selector。`1a8d256` 讓假 DOM 快取解析結果。這個測試檔在本機從 8.0 秒降到 0.8 秒，最慢的 Chat/Work 測試從 1.8 秒降到 90 毫秒。斷言沒有改。
- 15 new tests: 5 Grok status tests (anonymous en-US and zh-TW link pages, the paywall, signed-in Ready, and a signed-in reply that links to an external sign-in page) and 10 ChatGPT Chat/Work tests (send confirmation without a second click; capture of only the final answer; completion only from an action row that follows the answer, while earlier, historical, and user-message rows never complete; `Pro thinking` stays active; the pre-send guard rejects a new send during a live exchange and allows one after a finished exchange; a prompt that is literally `Pro thinking` still finishes).
- 新增 15 項測試：5 項 Grok 狀態測試（匿名的 en-US 與 zh-TW 連結頁、付費牆、已登入時的 Ready，以及一則連向外站登入頁的已登入回覆），以及 10 項 ChatGPT Chat/Work 測試（送出確認不必再點一次；只擷取最後的答案；只有跟在答案後面的動作列才算完成，較早的、歷史上的、以及使用者訊息上的動作列都不算完成；`Pro thinking` 維持進行中；送出前檢查在交換仍進行時拒絕新的送出，交換結束後允許送出一次；提示字面就是 `Pro thinking` 時，回合仍會結束）。
- About 14 legacy ChatGPT fixtures now place the copy control after the response, which is where the page puts it. Their assertions are unchanged.

- All four `v1.9.6` artifacts were SHA-256 checked against the digests GitHub recorded for the release. A reference `engine.js` (97,107 bytes) and `bootstrap.js` built locally from tagged commit `ef82ca4` each appear verbatim in all four shipped binaries, and the new identifiers match that reference exactly: `completionControlCounts` 2, `chatGptCompletionEvidence` 3, `data-user-message-bubble` 2, `turn-action-controls` 1. The host half (`src/`) could not be grepped, because Tauri brotli-compresses the embedded frontend; that half rests on the vite content hash rather than a direct grep. All four binaries embed `/assets/index-BlEOEqEe.js` and `/assets/index-DZ7I9tS3.css`, and building `ef82ca4` locally reproduced both. `v1.9.6` changes no frontend source, and that JS chunk is byte-identical to `v1.9.5`'s `index-BRFj9pkS.js`.
