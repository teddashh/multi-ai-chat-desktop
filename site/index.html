Stable release · v1.9.6

v1.9.6 handles ChatGPT's Chat/Work layout and signed-out Grok.

v1.9.6 follows ChatGPT's newer Chat/Work layout and shows signed-out Grok as Sign in instead of Ready.

01

ChatGPT's Chat/Work layout

Some ChatGPT accounts now get a newer page layout without the markers the app used to follow a conversation. The app confirms the send from your message bubble, reads only the final answer, and waits for the answer's action row before finishing. Controls on your own message never count as a finished answer.

02

Signed-out Grok shows Sign in

Anonymous grok.com shows Sign in / Sign up as links and keeps its send button, so the pane used to say Ready. It now shows Sign in, both on the homepage and on Grok's sign-up paywall after a send.

03

A replaced page fails the step

Since v1.9.5, a step waiting on a provider fails when that provider's page is replaced mid-turn, instead of silently waiting out the timeout. Detection is a new bootId. The prompt is not re-sent to the replacement page: a re-send could double-send if the original send had landed.

04

Composer fill is measured

Advisory STATUS_REPORT fields fill, fillChars, and fillMs carry character counts only. Prompt text never goes into the payload or the event log.

The v1.9.6 changes have automated coverage only and are not retested live. The Grok and ChatGPT adapter updates reach installed apps through the adapter update since 2026-09-30. The ChatGPT Chat/Work engine changes need v1.9.6.

A narrow trust boundary

No API keys. No telemetry. No hidden relay.

Your prompts go to the providers you select. The app does not add an account server or analytics layer between you and them.

✓Provider webviews receive zero Tauri permissions
  • 01

    Cookies and provider profiles remain in local app data, isolated per provider.

  • 02

    Only the bundled local control pane can call app commands.

  • 03

    Adapter updates are schema-validated JSON and cannot expand bundled URL scopes.

  • 04

    Snapshots are opt-in, local, and use one of four frozen privacy tiers.

  • 05

Honest boundaries

Automation follows changing websites.

Evidence is reported as evidence, not as a promise that every provider, account, or platform path works today.

Provider changes

A DOM or login-flow change can temporarily break automatic input, send, or completion detection until an adapter update ships.

Account rules remain

Subscriptions, quotas, regional rules, and challenges still apply. Claude requires login; Gemini and Grok blocks need user action.

Platform evidence differs

Windows launch is verified, macOS Apple Silicon is partially verified, and Linux packaging is currently CI-only.

These changes are not live-retested

The v1.9.6 changes have automated coverage only and have not been retested live. No Chat/Work account was available, and no signed-in Grok page was captured live, so the next live check is a Chat/Work account sending one prompt automatically and a signed-in Grok pane staying Ready. Installed apps pick up the Grok and ChatGPT adapter updates through the adapter update (at startup and every six hours) since 2026-09-30, but the ChatGPT Chat/Work engine changes need v1.9.6. An engine that goes silent or wedges while its page is never replaced still waits out the 10-minute inactivity window and the 60-minute absolute cap. Meta stays on inputStrategy: "default". Meta stop, new-session reset, and profile persistence remain unverified. Prior Windows launch evidence, the earlier Apple Silicon three-provider login report, and Linux CI-only packaging remain the current platform record. There is no new Windows, macOS, or Linux launch check for v1.9.6.

Frozen product scope

v1.9.6 keeps five choices with exactly four active. Meta AI is experimental, optional, and standby by default. Guest, email/mobile, or Facebook/Instagram sign-in must finish in the Meta pane. No sixth provider, marketplace, graph editor, embedded terminal agent, telemetry, self-updater, or new snapshot schema is planned.
